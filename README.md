# Hachimi 潛水艇工房

FFXIV 專用攻略與共用成品備料清單。四艘普通潛水艇從 1111 起步到 3124，含鬚鯨艦橋過渡，共八種零件各四件，38 種工房交付素材。

## 使用

- 一般連結唯讀，需以負責人核發的帳號與密碼登入，才能填數量、負責人與備註；解鎖 8 小時後失效。
- 已備妥包含已交工房的數量。例如備妥 100、交出 30，分別填 100 與 30。
- 修改後按該列儲存或 Enter。多人同時修改會提示衝突，不會直接覆蓋。
- 每項成品可設定夥伴認領量與其中已完成量。夥伴已完成包含在共用總量內，不重複相加。
- 材料預設保留於第 4 頁，可依已解鎖倉庫選第 1～5 頁並鎖定。位置變更需要 session 加重新輸入目前帳號的密碼；普通更新不接受位置欄位。此鎖定不替代遊戲內倉庫權限。
- 每項材料有留言紀錄，可記數量、分頁、格位。留言不自動加減庫存。
- 留料試算先保留工房直繳量，再分配加工用途，每項庫存只扣一次。
- 舊表庫存包含共用餘額與跨層重複紀錄，沒有自動合併匯入。

## 執行與部署

Node.js 24：`npm run build`、`npm test`、`npm run dev`。無外部套件。

部署為 Cloudflare Worker ESM，D1 綁定 `DB`；依序套用 `drizzle/` 的遷移。網站服務依 `.openai/hosting.json` 配置部署。

正式入口為 GitHub Pages，GitHub Actions 發布 `pages/`。Worker 僅負責共用資料、授權及備援介面。

後端 `EDIT_ACCOUNTS` 是私密 JSON 陣列，每筆包含 username、獨立 salt 和 PBKDF2-SHA256（100,000 次）hash，不儲存明文密碼。帳號由負責人核發，不提供自行註冊。`SESSION_SECRET` 簽署 8 小時登入 session，session 綁定帳號與憑證版本；移除帳號或更新 hash，舊 session 隨即失效。舊私人連結登入端點已停用，舊 session 不再有效。每 IP 每 15 分鐘最多 8 次登入嘗試；所有寫入仍由後端驗證登入。變更保留位置須重新輸入目前登入帳號的密碼。前端與 GitHub 內不含密碼或帳號 hash。

## 分工、船數與製作能力

共同主表以實名顯示兩人的認領、已備妥、待補；兩人已備妥自動相加，既有紀錄沿用。1～4 艘按鈕只切換需求試算，四艘共同進度與分工不變；其他艘數不提供共同數量編輯。CSV 保留兩人姓名和分項數量。

庫存頁可依工房成品、半成品、水晶／碎晶、其他原料篩選。可製作量先保留四艘工房直繳成品，再用餘量計算。單項可做量互相獨立，不能相加；整批依優先選項及工房清單順序共用一份庫存，產出需求先彙總才扣材料，處理共同原料與每次產出量。這是材料試算，未檢查角色製作能力、不自動扣庫存。

驗證：`node build.mjs`、`node test.mjs`、`node craft-test.mjs`。

## 日常操作介面

主頁只顯示需求、已準備、還缺與兩人待補量，按「填進度」填寫兩人認領及完成量，合計自動計算。已交工房與備註收於展開區。原料頁分成「填現有材料」及「看能做什麼」兩步，未填與已記錄分開；配方、倉庫、留言及完整需求試算均由明確按鈕展開。

## 輪替與解鎖保留

完整輪替為 1111 → 1121 → 3113 → 1123 → 3124；換下的零件保留，重裝不重做。每艘八種零件，四艘32件；38種交付成品。胡桃木材每艘18+24=42、四艘168。切換階段僅顯示該步新零件的增量；分工仍是四艘全程。

四張設計圖只解鎖一次，不乘四。待確認時保守視為未解鎖，五種材料獨立保留；紅木木材不足會保護其原木及風之碎晶。後端拒絕降低必留庫存；計算可製作量也不能消耗。做解鎖木材時先登錄成品，再更新消耗原料。已有解鎖只改狀態、不扣料；實際繳交需二次確認、原子交易扣除一次，庫存不足或版本衝突全部不變。不能以留言當交付。

「這一步已交工房」只更新已交成品，原料不動。「補舊紀錄」用於未曾登錄的歷史船件；增加已準備及已交相同數量，現有實體庫存不變，亦不冒認為任何人的新貢獻。

船數/階段可存在此帳號；未登入存在這台裝置。全站搜尋支援素材、戰友、倉庫頁格與留言；材料旁可複製名字，材料幫手可展開缺底材與來源。位置有核對座標才直接列出，其餘導向精確物品來源，避免虛構採集點。

檢查：node build.mjs、node test.mjs、node craft-test.mjs、node workflow-test.mjs。後端遷移0002必須先部署成功，再更新GitHub Pages前端。

## 認領與取得方式標籤

未明確認領的剩餘工作顯示「未認領」，不預設歸任何人。分工表只填夥伴名字、夥伴認領、兩人已備妥；勾選「剩餘認領」才自動分配餘量給第一人。總量唯讀合計，已交付為其子集。遷移0003新增self_claimed預設0，保留全部歷史數量，不憑舊庫存推定認領。

19種材料的軍票/部落商店來源由官方物品頁提取；每筆保留精確商店物品連結、購買/交換幣別、軍階及座標。標籤區分成品直接取得與底材取得；金幣購買不標成軍票。聲望條件只在核對後列出，其他引導至官方商店。主表與庫存頁可篩選軍票/部落來源。
